# AI_Project

## Project Description:
We propose developing an AI-powered clothing classification and outfit recommendation system. Given a user-uploaded clothing image, a computer vision model will identify the primary clothing category, focusing on tops, bottoms, jackets, and dresses. We will fine-tune a pretrained vision model, such as a Vision Transformer (ViT), using a labeled fashion dataset.
After classification, the system will extract additional clothing characteristics such as color and style. A fashion-specific vision model such as FashionCLIP may be used to help identify style-related attributes. The recommendation system will then combine these attributes with predefined fashion principles, including color compatibility, structural style, and clothing-category compatibility.
A locally hosted large language model (LLM), such as Qwen2.5-7B-Instruct, will be incorporated into the recommendation process. Rather than allowing the LLM to independently determine what clothing combinations are appropriate, it will receive the results of the computer vision model and the project's fashion rules and generate several outfit suggestions with short explanations. This creates a hybrid system combining machine learning, computer vision, rule-based reasoning, and natural language generation.

## How to Run Designer AI

**Requirements:** Python 3.12 and Git.

**1. Clone the repository:**
```bash
git clone https://github.com/maddiecg/AI_Project.git
cd AI_Project
```

**2. Install dependencies:**
```bash
python -m pip install -r requirements.txt
```

**3. Start the application:**
```bash
python -m uvicorn Backend.API.routes:app --reload
```

**4. Open the website:**

Visit http://127.0.0.1:8000/ in your browser.

Upload a clothing image to receive an AI-generated clothing category prediction, automatic color detection, and outfit recommendations.

**5. Stop the application:**

Press `Ctrl + C` in the terminal.

**Note:** The trained model is included in the project, so no additional training or dataset download is required.

## Project Features

The current application provides an image-based clothing classification and
outfit-suggestion workflow:

- **Image upload:** Select a JPG, JPEG, PNG, or WEBP image from the AI Stylist
  section of the website.
- **Clothing classification:** The trained model predicts one of four
  categories: bottoms, dresses, shoes, or tops. The result includes the
  classifier's highest softmax score, displayed as a confidence percentage.
- **Color estimation:** A pixel-based heuristic estimates the image's dominant
  color. It is not a garment-segmentation model, so backgrounds, lighting, and
  patterns can affect the result.
- **Outfit suggestions:** Hand-authored category and color rules produce two
  suggested outfit items and a short explanation. Recommendations are
  deterministic; they are not generated by an LLM or a trained fashion
  recommender.
- **Website results:** The AI Stylist section displays the predicted category,
  color, confidence, suggested items, and explanation.
- **Sample closet:** The My Closet section displays six example items and
  supports filtering by category. These are static examples, not a saved
  personal wardrobe, and uploaded images are not added to the sample closet.
- **Fashion inspiration and responsive navigation:** The page includes
  editorial sample looks, section navigation, and a mobile navigation menu.

The Saved Outfits link and some styling calls to action are presentation
elements only; saving outfits is not currently implemented. A manual color
override is supported by the Python recommendation function and API, but the
website does not currently provide a color-entry control.

## Using the Website

1. Start the server using the steps in [How to Run Designer AI](#how-to-run-designer-ai).
2. Open [http://127.0.0.1:8000/](http://127.0.0.1:8000/) in a browser.
3. Navigate to **AI Stylist** (or select **Style Me**) and choose an image of
   one clothing item. The application accepts JPG, JPEG, PNG, and WEBP files.
4. Wait for the result to appear. The page displays the predicted category,
   estimated color, classifier confidence, outfit suggestions, and a brief
   explanation.
5. To browse the static example closet, choose **My Closet** and use its
   category filters.

The first request may take longer while the model is loaded. The API processes
the uploaded image in a temporary file and removes that file after processing.
If the image cannot be processed, an error message is displayed in the result
area.

### Recommendation API

The website sends an image as multipart form data to `POST /api/recommend`.
The endpoint returns JSON with `category`, `color`, `confidence`,
`recommendations`, and `explanation` fields. For example, with the server
running:

```bash
curl -X POST http://127.0.0.1:8000/api/recommend \
  -F "image=@path/to/clothing.jpg"
```

An optional `color` form field can override automatic color detection for API
or programmatic use.

| Area | Technologies and role |

Python package dependencies are listed in [`requirements.txt`](requirements.txt).
The frontend is served as static files by FastAPI; it does not use a separate
JavaScript framework or frontend package manager.

## AI Method and Training

The AI classifier predicts **bottoms, dresses, shoes, or tops**. Product
article types are mapped into these broader classes during data preparation.
The model uses MobileNetV2 pretrained on ImageNet as a frozen feature extractor,
with a newly trained four-unit softmax classification layer. Input images are
converted to RGB, resized to 224 × 224 pixels, and normalized. Random horizontal
flips, small rotations, and zooms augment training examples.

Training uses Adam with an initial learning rate of 0.001, sparse categorical
cross-entropy, batches of 32, and up to 10 epochs. The data-preparation script
creates deterministic, stratified 70% training, 15% validation, and 15% test
splits with random seed 42. The best validation-accuracy checkpoint is saved;
early stopping and learning-rate reduction on a validation-loss plateau are
also enabled.

To reproduce training, first make sure the dataset metadata and extracted
images are available under `Data/` (the metadata file is `Data/styles.csv`).
Then run:

```bash
python Notebooks/prepare_data.py
python Backend/train_model.py
python Notebooks/modelEvaluation.py
```

Data preparation writes split manifests to `Data/prepared/`. Training writes
the model, class names, and training history to `Backend/`; evaluation writes
per-image predictions, a classification report, and a confusion-matrix image
to `Data/evaluation/`. Dataset files and split manifests may not be present in
every checkout. Running the website with the included trained model does not
require retraining.

Color estimation and outfit recommendation are separate from the trained
classifier: dominant color is estimated with HSV-based pixel rules, and outfit
items are selected from a manually authored color-matching table and category
rules. Neither part is a learned AI model.

## Model Performance

The saved evaluation report records performance on **4,032 test images**:

| Category | Precision | Recall | F1 score | Test examples |
|---|---:|---:|---:|---:|
| Bottoms | 0.99 | 0.97 | 0.98 | 376 |
| Dresses | 0.60 | 0.38 | 0.46 | 69 |
| Shoes | 1.00 | 1.00 | 1.00 | 1,385 |
| Tops | 0.98 | 0.99 | 0.99 | 2,202 |
| **Macro average** | **0.89** | **0.84** | **0.86** | **4,032** |
| **Weighted average** | **0.98** | **0.98** | **0.98** | **4,032** |

**Overall test accuracy: 98.29%.** The test set is imbalanced: tops and shoes
make up about 89% of examples, while dresses make up only 69 examples. The low
dress recall (0.38) means the model misses many dress examples despite its high
overall accuracy. Macro-averaged metrics, which give each category equal weight,
provide a more balanced view than accuracy or weighted averages alone.

These metrics measure only image-category classification on the saved test
split. The project does not have a measured accuracy score for color detection
or recommendation quality, and no latency or throughput benchmark is recorded.
Softmax confidence is not shown to be calibrated and should not be interpreted
as a guarantee. Product-style test images may also differ from everyday user
photos, backgrounds, and lighting.

## Current Scope and Future Work

The current implementation is narrower than the original proposal. The
proposal mentioned a Vision Transformer, FashionCLIP-style style attributes,
and a locally hosted Qwen model. Those components are not part of the current
code; the implemented classifier is MobileNetV2, and recommendations use
deterministic rules. Potential next steps include improving dress recall with
more representative data, testing color detection on garment-specific regions,
evaluating recommendation usefulness with users, adding preference-aware
recommendations, and measuring inference performance on documented hardware.
